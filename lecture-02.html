§1 · The Von Neumann model§1 · نموذج فون نيومان

One idea from 1945 that every computer you own still obeys.فكرةٌ واحدة من عام 1945 لا يزال كل حاسوبٍ تملكه يُطيعها.

In 1945 John Von Neumann described the stored-program computer: instructions and data live in the same memory and travel over the same wires. That single decision is why a computer is general-purpose — feed it different instructions and it becomes a different machine, with no rewiring. Every part hangs off a shared system bus.

في عام 1945 وصف جون فون نيومان حاسوب البرنامج المخزَّن: التعليمات والبيانات تعيش في الذاكرة نفسها وتنتقل عبر الأسلاك نفسها. هذا القرار وحده هو سبب كون الحاسوب عامَّ الغرض — أعطِه تعليماتٍ مختلفة فيصير آلةً مختلفة، دون إعادة توصيل. وكل جزءٍ يتّصل بـناقل النظام (system bus) المشترك.
CPU
Processorالمعالج

Executes instructions. Holds the ALU (arithmetic + logic), the Control Unit (sequencing) and the registers.يُنفّذ التعليمات. يحوي وحدة الحساب والمنطق (ALU) ووحدة التحكّم (CU) والمسجّلات.

Memory · RAM
Working memoryذاكرة العمل

Holds the programs and data in use right now. Fast, but forgotten when power is cut.تحمل البرامج والبيانات المُستخدَمة الآن. سريعة، لكنها تُنسى عند انقطاع الطاقة.

§2 · The fetch–decode–execute cycle§2 · دورة الجلب — فكّ الترميز — التنفيذ

The three-beat rhythm every instruction dances, billions of times a second.الإيقاع الثلاثي الذي ترقصه كلّ تعليمة، مليارات المرّات في الثانية.

The CPU repeats three steps forever. Fetch: copy the instruction at address PC into IR, then advance PC. Decode: the Control Unit works out what the instruction means. Execute: the ALU (or a memory access) carries it out. A printed page can only list these steps. Press Step and watch a tiny four-line program — load two numbers, add them, store the result — actually run.

يكرّر المعالج ثلاث خطواتٍ إلى الأبد. الجلب: انسخ التعليمة الموجودة في العنوان PC إلى IR، ثم زِد PC. فكّ الترميز: تُحدّد وحدة التحكّم معنى التعليمة. التنفيذ: تنفّذها وحدة الحساب والمنطق (أو عملية وصولٍ للذاكرة). الصفحة المطبوعة تستطيع سرد هذه الخطوات فقط. اضغط خطوة وشاهِد برنامجًا صغيرًا من أربعة أسطر — حمِّل عددين، اجمعهما، خزّن الناتج — يعمل فعلًا.

§3 · The memory hierarchy§3 · التسلسل الهرمي للذاكرة

Fast is small, big is slow — so the CPU searches from the top down.السريع صغير، والكبير بطيء — فيبحث المعالج من الأعلى نزولًا.

There is no single memory that is both huge and instant, so computers stack several: tiny, blazing registers and cache next to the CPU; large, slow RAM and disk further out. When the CPU needs a value it looks in the nearest level first; if it is not there (a miss) it tries the next, paying more time at each step. Try a cache hit and then a cache miss and watch the total wait grow.

لا توجد ذاكرةٌ واحدة ضخمةٌ وفوريةٌ معًا، لذا تُكدّس الحواسيب عدّة طبقات: مسجّلاتٌ وذاكرة كاش صغيرةٌ فائقة السرعة بجوار المعالج؛ وذاكرة RAM وقرصٌ كبيران بطيئان أبعد. حين يحتاج المعالج قيمةً يبحث في أقرب طبقةٍ أولًا؛ فإن لم يجدها (إخفاق/miss) جرّب التالية، دافعًا وقتًا أكبر في كل خطوة. جرّب إصابة كاش ثم إخفاق كاش وراقب مجموع الانتظار يتضخّم.

💡 What to noticeما الذي نلاحظه؟ A cache miss to RAM costs roughly 60× a hit — that jump is why fast code keeps the data it reuses close together (the principle of locality). The hierarchy is a bet: keep recently-used data near the top and most look-ups win at L1/L2 before ever paying the RAM price. إخفاق الكاش نزولًا إلى RAM يكلّف نحو 60 ضعف الإصابة — وهذه القفزة هي سبب حرص الشيفرة السريعة على إبقاء بياناتها المُعاد استخدامها متجاورة (مبدأ المحلّية). فالتسلسل الهرمي رهانٌ: أبقِ البيانات المُستخدَمة حديثًا قرب القمّة، فتفوز معظم عمليات البحث عند L1/L2 قبل أن تدفع ثمن RAM أصلًا.

§4 · System software & the OS§4 · برمجيات النظام ونظام التشغيل

The layer that stands between your program and the bare metal.الطبقة التي تقف بين برنامجك والعتاد المجرَّد.

Your programs almost never touch the hardware directly. The operating system sits in between — it schedules which program runs, hands out memory, organises files, and talks to devices through drivers. At its core is the kernel, which alone runs in privileged mode; when your program needs the hardware it asks the kernel with a system call. That wall is what stops one buggy app from taking down the whole machine.

برامجك لا تلمس العتاد مباشرةً تقريبًا أبدًا. يقف نظام التشغيل بينهما — يجدول أيّ برنامجٍ يعمل، ويوزّع الذاكرة، وينظّم الملفّات، ويخاطب الأجهزة عبر المُشغّلات (drivers). وفي قلبه النواة (kernel) التي وحدها تعمل في الوضع المُمتاز؛ وحين يحتاج برنامجك العتادَ يطلبه من النواة عبر نداء نظام (system call). هذا الجدار هو ما يمنع تطبيقًا مُعطَّلًا واحدًا من إسقاط الجهاز كلّه.
The stack, top to bottomالمكدّس من الأعلى للأسفل: User applications → system utilities → Operating System (kernel) → device drivers / firmware → hardware. A system call is the doorway from the top half to the privileged bottom half. تطبيقات المستخدم ← أدوات النظام ← نظام التشغيل (النواة) ← المُشغّلات/البرامج الثابتة ← العتاد. ونداء النظام هو الباب من النصف العلوي إلى النصف السفلي المُمتاز.

§5 · Cloud computing§5 · الحوسبة السحابية

Renting computing over the Internet instead of owning it.استئجار الحوسبة عبر الإنترنت بدل امتلاكها.

Cloud computing means using servers, storage and software on demand over the Internet. The three service levels differ by how much the provider manages for you:

الحوسبة السحابية تعني استخدام الخوادم والتخزين والبرمجيات عند الطلب عبر الإنترنت. وتختلف المستويات الثلاثة بحسب كم يديره المزوّد نيابةً عنك:
IaaS
Infrastructureالبنية التحتية

Raw virtual machines, storage, networking. You install everything above it. Like renting a car. (AWS EC2)أجهزة افتراضية وتخزين وشبكات خام. تُثبّت كل ما فوقها بنفسك. كاستئجار سيارة. (AWS EC2)

PaaS
Platformالمنصّة

You upload code; the platform runs and scales it. Like taking a taxi. (App Engine, Heroku)ترفع الشيفرة؛ والمنصّة تشغّلها وتوسّعها. كركوب سيارة أجرة. (App Engine، Heroku)

SaaS
Softwareالبرمجية

A ready-to-use application in the browser. Like riding the bus. (Gmail, Microsoft 365)تطبيقٌ جاهز للاستخدام في المتصفّح. كركوب الحافلة. (Gmail، Microsoft 365)

Behind it allخلف ذلك كلّه: virtualisation — one physical server hosts many isolated virtual machines; containers (Docker) are a lighter version that share the host kernel, so they start in a fraction of the time. المحاكاة الافتراضية — خادمٌ فيزيائي واحد يستضيف عدّة أجهزة افتراضية معزولة؛ والحاويات (Docker) نسخةٌ أخفّ تتشارك نواة المضيف، فتبدأ في جزءٍ يسير من الزمن.

§6 · CPU vs GPU — why AI needs the GPU§6 · المعالج المركزي مقابل الرسومي — لماذا يحتاج الذكاء الاصطناعي المعالجَ الرسومي

A few brilliant workers, or thousands of simple ones — race them.عمّالٌ قلائل بارعون، أم آلافٌ بسطاء — أجرِ السباق بينهم.

A CPU has a few powerful cores tuned for complex, sequential work. A GPU has thousands of simple cores that all do the same operation at once. Training a neural network is millions of independent multiplications — exactly the job thousands of small cores devour in parallel. Press Play to send the same batch of 64 multiplications to both and watch them race.

يملك المعالج المركزي نوىً قليلةً قويّة مُهيّأة للعمل المتسلسل المعقّد. أمّا المعالج الرسومي فيملك آلاف النوى البسيطة التي تُنفّذ العملية نفسها دفعةً واحدة. وتدريب شبكةٍ عصبية هو ملايين عمليات الضرب المستقلّة — وهو تحديدًا ما تلتهمه آلاف النوى الصغيرة على التوازي. اضغط تشغيل لإرسال الدفعة نفسها (64 عملية ضرب) إلى كليهما وشاهِد السباق.

💡 What to noticeما الذي نلاحظه؟ The GPU is not faster per core — its cores are actually slower. It wins by doing many at once. This only helps when the work splits into independent pieces (multiplications, pixels, matrix rows). Give a GPU one long sequential task and the CPU wins easily — which is why a real computer keeps both. المعالج الرسومي ليس أسرع في النواة الواحدة — بل نواه أبطأ فعلًا. إنّما يفوز بتنفيذ الكثير دفعةً واحدة. وهذا لا ينفع إلّا حين ينقسم العمل إلى قطعٍ مستقلّة (عمليات ضرب، بكسلات، صفوف مصفوفة). أمّا لو أعطيتَه مهمّةً متسلسلة طويلةً واحدة لفاز المعالج المركزي بسهولة — ولهذا يحتفظ الحاسوب الحقيقي بكليهما.

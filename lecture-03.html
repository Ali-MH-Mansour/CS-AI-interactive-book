§1 · What is an algorithm?

A finite recipe that always finishes — and the five rules it must obey.

An algorithm is a finite, ordered set of unambiguous instructions that solves a class of problems and always terminates after a finite number of steps. The word comes from the 9th-century mathematician Muhammad ibn Musa al-Khwarizmi, whose treatise on arithmetic brought systematic calculation to European mathematics.

ℹ︎ The five properties: Finiteness (it must stop) · Definiteness (each step has one meaning) · Input (zero or more) · Output (one or more results) · Effectiveness (each step is doable with basic operations). Break any one and it is no longer an algorithm.
Algorithm
The method

An abstract description of a solution. Like a recipe.

Program
The method, written

The algorithm expressed in one language. Like the recipe printed on paper.

Process
The method, running

A program using real memory and CPU time. Like a cook following it.

§2 · Writing it down — flowcharts & pseudocode

Two ways to capture an algorithm before it becomes code.

Before writing code we sketch the algorithm. A flowchart draws it: an oval for start/end, a rectangle for a process step, a diamond for a decision, a parallelogram for input/output, arrows for the flow. Pseudocode writes it in plain-but-structured words — not executable, but a bridge to real code.

   ┌─────────┐        FUNCTION max(A, B)
   │  Start  │          IF A > B THEN
   └────┬────┘            RETURN A
    Input A, B          ELSE
        ↓                 RETURN B
     ┌──┴──┐            END IF
     │A > B?│           END FUNCTION
     └┬───┬┘
    Yes   No            ← the diamond (A > B?) is the decision;
   max=A max=B            each branch is one path of §3's "selection".
        ↓
    Output max  →  End

§3 · The three building blocks

Sequence, selection, iteration — every algorithm is made of only these.

Böhm and Jacopini proved in 1966 that any algorithm can be built from exactly three control structures. Sequence: steps run in order. Selection: a condition chooses a branch (IF…ELSE). Iteration: a block repeats (FOR, WHILE). A printed page lists the loop; press Step below and watch one actually run — a counted loop that adds up 1 + 2 + … + 10. And sum is an accumulator: it carries the running total across iterations — lose it and each pass would forget the last.

§4 · How fast is it? — complexity & Big-O

Correct is not enough — it must scale. Watch a sorted search halve its work each step.

Time complexity counts basic operations as the input size n grows, written in Big-O — the worst-case growth rate, ignoring constants. Linear search checks every element: O(n). Binary search needs a sorted array and throws away half the remaining elements on every comparison: O(log n). Press Step and watch binary search find a value — see the live range shrink and the discarded halves fade out.

Binary search for 22 in a sorted array

animated
💡 What to notice Binary search finds 22 in 3 comparisons; a linear scan would touch 5 elements to reach index 4. The gap looks small on 7 items but explodes with size: on a million sorted items binary search needs at most 20 comparisons — because each step halves what is left (that is what O(log n) means). The catch: this only works because the array is sorted. No sort, no binary search.

§5 · From source code to a running program

The toolchain — and the one place you spend your day: the IDE.

Source code (.py, .c, .java) is not what the CPU runs. A compiler translates the whole file to machine code ahead of time (C, Go); an interpreter executes it line by line (Python); some languages compile to bytecode that a virtual machine runs (Java). An IDE bundles the editor, the build/run button, the debugger and error highlighting into one window — and from day one you keep it all under version control with Git.

Compiler
Translate, then run

Whole file → machine code before running. Fast to run. (C, C++, Go)

Interpreter
Run line by line

Executes the source directly, one line at a time. Flexible. (Python)

IDE + Git
One workspace

Editor, run button, debugger, error hints — plus a full history of every change.

▶ Your first three Git commands: git init (start a repo) · git add hello.py (stage a file) · git commit -m "Initial commit" (save a snapshot). Even for a solo project this gives you an undo button for your whole history.

Chapter summary

🎬 You just watched

An algorithm is a finite, definite recipe that must terminate. Every one is built from sequence, selection and iteration — you saw a counted loop reuse one line 10 times to reach 55. Efficiency is measured in Big-O: binary search halves its work each step (O(log n)) and beats linear search (O(n)) on any sorted array.

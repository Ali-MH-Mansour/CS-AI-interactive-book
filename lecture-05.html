Information Security

What we protect and what attacks it — the CIA triad, malware and social engineering, and the cryptography that defends it: symmetric and public-key encryption, hashing and digital signatures, watched step by step.

§1 · What security protects — the CIA triad

Every security measure serves one of three goals: keeping information secret, correct, or available.

Information security protects information and systems from unauthorised access, disclosure, alteration or disruption. Its goals are captured by three properties, together called the CIA triad. They matter together: encrypting data (confidentiality) is useless if an attacker can silently corrupt it (integrity) or knock the whole service offline (availability).

PropertyMeaningFails when…Safeguard
ConfidentialityOnly authorised parties can read itA password database is leakedEncryption, access control
IntegrityAccurate, not alteredAn attacker changes a transfer amountHashing, digital signatures
AvailabilityAccessible when neededA server is knocked offlineBackups, redundancy, DDoS protection
➕ Three more ideas for accountability: Authentication — proving who you are; Authorisation — deciding what you may do once authenticated; Non-repudiation — you cannot later deny an action (provided by digital signatures, §3.4).

§2 · Threats and attacks

A vulnerability is a weakness; a threat is potential harm; an attack is an attempt to exploit the weakness.

2.1 Malware

Malware is any program written to damage or gain unauthorised control of a system.

TypeHow it behaves
VirusAttaches to a file; spreads when that file is run
WormSelf-replicating; spreads across a network without user action
TrojanDisguised as useful software; hides a malicious payload
RansomwareEncrypts the victim's files and demands payment
SpywareSecretly collects keystrokes, browsing, credentials
RootkitHides deep in the system for persistent, stealthy control

2.2 Social engineering & denial of service

Social engineering manipulates people rather than machines: phishing (fraudulent messages imitating a trusted sender), pretexting (inventing a believable scenario — "I'm from IT"), and baiting (leaving an infected USB stick). A Denial-of-Service (DoS) attack floods a system so real users cannot reach it — an attack on availability; a DDoS launches the flood from a botnet of thousands of machines at once.

🧑 The human is the weakest link: The strongest encryption is bypassed if a user simply tells an attacker their password. Security-awareness training is a genuine defence, not an afterthought.

2.3 Common web attacks

AttackWhat it doesBasic defence
SQL injectionInjects malicious SQL into an input to read/alter the DBParameterised queries
XSSInjects JavaScript that runs in another user's browserEscape / sanitise output
CSRFForges a request from a logged-in user's browserAnti-CSRF tokens
💉 How SQL injection works: A login query built by string concatenation — "... WHERE name = '" + input + "'" — with the input ' OR '1'='1 becomes ... WHERE name = '' OR '1'='1', always true: the attacker logs in without a password. The fix is never to paste user text into a query — use parameterised queries that keep data and code separate.

§3 · Cryptography — protecting confidentiality & integrity

Encryption turns readable plaintext into unreadable ciphertext. The security lies in the key, not in hiding the algorithm.

There are two families. In symmetric encryption the same secret key encrypts and decrypts (AES) — very fast, but both parties must already share the key: the key-distribution problem. In asymmetric (public-key) encryption each party has a key pair — a public key shared with everyone and a private key kept secret (RSA, ECC); what one key locks, only the other unlocks. 💡 What to notice In symmetric mode the same key K appears at both ends — fast, but that key somehow had to reach the other side safely first. In asymmetric mode the two keys differ: anyone may encrypt with Alice's public key, yet only her private key decrypts — so no shared secret ever travels. That is why the real web uses both (hybrid encryption): slow public-key crypto runs once just to agree a fresh symmetric session key, then the fast symmetric key encrypts all the traffic — exactly what HTTPS does (§5.3).

3.3 Hash functions

A cryptographic hash function takes any input and produces a fixed-size digest (a "fingerprint"). It is deterministic (same input → same digest), one-way (you cannot reverse it), collision-resistant, and has the avalanche effect (one changed bit changes the whole digest). SHA-256 is secure; MD5 and SHA-1 are broken. Hashes verify that a file was not altered, and let a system store the hash of a password (with a random salt) rather than the password itself.

3.4 Digital (electronic) signatures

A digital signature uses public-key cryptography in reverse to prove who created a message and that it was not changed. The signer hashes the document and encrypts the hash with their private key; anyone verifies it with the signer's public key. 💡 What to notice Verification succeeds only when two independently-computed digests match: the one Bob gets by hashing the received document, and the one he recovers by decrypting the signature with Alice's public key. Press Tamper and a single changed character makes Bob's fresh hash differ (the avalanche effect of §3.3) — the digests no longer match and verification fails. So a digital signature gives three guarantees at once: authentication (only Alice's private key could produce it), integrity (any change breaks the match), and non-repudiation (Alice cannot deny signing). A Certificate Authority (CA) then vouches that the public key really is Alice's.

§4 · Authentication & access control

Authentication asks "are you who you claim?" using one or more factors from different categories.

Factor"Something you…"Example
KnowledgeknowPassword, PIN
PossessionhavePhone, security token, smart card
InherenceareFingerprint, face, iris
🔐 Two-factor authentication (2FA): 2FA/MFA combines factors from different categories (a password and a code from your phone). Even if your password is stolen, the attacker still lacks the second factor. Pair it with strong, unique passwords (use a password manager) and the principle of least privilege: give each user and program only the access it truly needs.

§5 · Practical defences — defence in depth

Security is built in layers. No single control is enough.

Firewall
A controlled gate

Monitors and filters network traffic against rules, between a trusted network and the untrusted internet.

VPN
Encrypted tunnel

Wraps your traffic in an encrypted tunnel across a public network — essential on untrusted Wi-Fi.

HTTPS / TLS
The padlock

HTTP inside a TLS channel: verifies the site's certificate, agrees a symmetric session key, encrypts everything in transit (the hybrid scheme of §3).

🧹 Everyday hygiene: Keep software updated — most attacks exploit a known hole a patch already fixed. Back up by the 3-2-1 rule (3 copies · 2 media · 1 off-site) — the only reliable defence against ransomware. Run least privilege, and use anti-malware + spam/phishing filters.

§6 · Physical & organisational security

Technical controls are undermined if an attacker can simply reach the machine. Physical security — locked server rooms, access cards, surveillance, environmental protection (power, cooling, fire suppression). Organisational security — clear policies, staff awareness training, an incident-response plan, and regular audits. Standards such as ISO/IEC 27001 and Russia's ФСТЭК/ГОСТ requirements define how organisations manage information security systematically.

Chapter summary

🎬 You just watched

Security protects confidentiality, integrity and availability (the CIA triad) against malware, social engineering, DoS and web attacks. You stepped a message through symmetric (one shared key) and asymmetric (public + private pair) encryption, and saw why the web combines both. You then signed and verified a document — and watched a single tampered character break the hash match, the core of a digital signature. On top sit authentication (2FA), and layered defences: firewalls, VPNs, HTTPS/TLS, updates and backups.
